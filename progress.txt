## Story V2-002: JWT Session Management (login, refresh, logout) — DONE
Files touched:
- backend/src/routes/auth.ts (rewritten — added login, refresh, logout endpoints + requireAuth middleware)
- backend/src/db/index.ts (modified — idempotent revoked_at column addition to refresh_tokens)
- backend/src/routes/__tests__/auth.test.ts (rewritten — 39 tests covering all endpoints + middleware)
- src/lib/apiFetch.ts (rewritten — added token management + silent refresh interceptor)

What was built:
- POST /api/auth/login: validates email/password, returns access token (15m JWT) + refresh token (7-day opaque), emits user_login WAL event
- POST /api/auth/refresh: validates refresh token hash against DB, checks revoked_at + expires_at, rotates tokens (old revoked, new pair issued)
- POST /api/auth/logout: sets revoked_at timestamp on refresh token, returns 401 for invalid/already-revoked tokens
- requireAuth middleware: verifies JWT from Authorization header, returns 401 "Token expired" for expired tokens (distinct from "Invalid token"), populates req.userId/req.userEmail
- Frontend apiFetch: stores tokens in localStorage, attaches Authorization header, intercepts 401 "Token expired" responses and silently refreshes with deduplication for concurrent requests

Key decisions:
- Changed REFRESH_TOKEN_EXPIRES_DAYS from 30 to 7 per AC
- Added revoked_at column idempotently via pragma table_info (same pattern as preferred_model)
- Refresh token rotation: old token revoked on every refresh, preventing replay attacks
- Silent refresh deduplication: concurrent 401s share a single refresh promise to avoid token rotation races
- requireAuth exported as named export alongside default router for flexible middleware usage

- Socket path uniqueness: includes `process.pid` and `Date.now()` to avoid collisions across concurrent runs

## Story OC-015: Robust OpenCode Error Handling & Orphan Cleanup — DONE
Files touched:
- backend/src/lib/execution-engine.ts (modified — OpenCode error classifier, classified error WAL payloads in both sequential + parallel paths)
- backend/src/lib/opencode-parser.ts (modified — malformed JSON recovery with counter, rate limit detection from raw text in event stream)
- backend/src/routes/pipeline.ts (modified — OpenCode server health monitor with restart attempt, orphan process cleanup function)
- backend/src/server.ts (modified — cleanupOrphanRuns() called at startup)

What was built:
- **Error classifier** (`classifyOpenCodeError`): Categorizes OpenCode failures into 7 types: `not_installed`, `api_key_invalid`, `model_not_available`, `rate_limited`, `server_crashed`, `malformed_output`, `timeout`, `unknown`. Each has `retryable` flag — non-retryable errors (wrong API key, missing model) skip all retry logic and fail immediately with clear user-facing message in WAL.
- **Enhanced WAL payloads**: `story_failed` events now include `error_category`, `error_message`, `agent_type`, `exit_code` for OpenCode runs. Enables UI to show "Provider API key invalid" vs generic "max_retries" messages.
- **Server crash detection**: Pipeline trigger spawns a 5s health check interval that monitors OpenCode server `isAlive()`. On crash: attempts one restart (uses existing `OpenCodeServer.restart()`). On restart failure: kills execution engine process group, emits `opencode_server_crash` WAL event, run fails gracefully.
- **Malformed JSON recovery**: `OpenCodeStreamParser.parseLine()` now tracks malformed line count, logs first occurrence per burst, and specifically detects rate limit errors in plain text output (429, "rate limit", "too many requests", "quota exceeded"). Rate limit lines emitted as yellow `[Rate Limited]` terminal entries with extracted wait time.
- **Orphan process cleanup**: `cleanupOrphanRuns()` exported from pipeline.ts, called by server.ts at startup. Scans `pipeline_runs WHERE status IN ('running', 'paused')`, kills engine PIDs (process group SIGTERM) + OpenCode server PIDs, marks runs failed, emits `run_finished` WAL events with `reason: 'orphan_cleanup'`.
- **Rate limit 429 detection from event stream**: Parser detects `429`, `rate limit`, `too many requests`, `quota exceeded`, `tokens per min` in raw text lines. Extracts `retry-after` seconds when available. Emits semantic + terminal entries for UI display.

Key decisions:
- Error classification runs ONLY for `agentType === 'opencode'` — Claude path keeps existing generic retry behavior (no regression risk)
- Non-retryable errors bypass retry counter entirely — prevents 3 wasted retries when API key is wrong
- `extractProviderHint()` and `extractModelHint()` parse stderr to include provider/model name in error message
- Server health check interval (5s) is a reasonable balance between detection latency and overhead
- Orphan cleanup kills process group (-pid SIGTERM) first, falls back to individual PID — handles both detached process groups and direct children
- Malformed JSON counter resets on first valid JSON line — prevents log spam during recovery
- Pre-existing type errors (rate-limiter.ts, run-queue.ts) unchanged — verified not introduced by OC-015
