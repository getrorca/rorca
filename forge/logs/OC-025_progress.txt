## Story OC-025: Claude Subscription Auth Detection — DONE

Files touched:
- backend/src/lib/claude-auth.ts (NEW) — credential detection, login/logout subprocess management, SSE event firing
- backend/src/routes/config.ts — added GET /api/config/claude-auth, POST /login, POST /logout routes + import
- backend/src/routes/pipeline.ts — added Claude auth gate in pipeline trigger (blocks when disconnected + RORCA_AGENT=claude)
- src/panels/SettingsPanel.tsx — added ClaudeAuthStatus component, shown when Claude engine selected

What was built:
- Backend reads ~/.claude/.credentials.json (primary), falls back to ~/Library/Application Support/Claude/config.json (oauth:tokenCache), final fallback checks claude CLI binary availability
- GET /api/config/claude-auth returns { connected, email?, tier?, expiresAt?, cliInstalled, cliVersion } — no raw token exposed
- POST /api/config/claude-auth/login spawns `claude auth login` detached, polls every 2s for credential changes, fires SSE `claude_auth_connected` event
- POST /api/config/claude-auth/logout spawns `claude auth logout`, fires SSE `claude_auth_disconnected` event
- Frontend shows green/amber status card with email, tier, CLI version; Connect/Disconnect buttons; expiry warning within 24h
- Frontend listens to SSE events for real-time auth state changes without page reload
- Pipeline trigger returns 403 `claude_not_authenticated` with Settings deep-link when Claude is selected but not authenticated

Key decisions:
- Claude CLI stores OAuth token in encrypted form in ~/Library/Application Support/Claude/config.json (not ~/.claude/.credentials.json). The .credentials.json path is checked first for newer CLI versions but doesn't exist yet. Fallback chain: credentials.json → desktop config oauth:tokenCache → CLI binary detection.
- Used dynamic import for claude-auth in pipeline.ts to keep it lazy-loaded
- CLAUDECODE + CLAUDE_CODE_ENTRYPOINT env vars must be unset when spawning claude CLI commands to avoid "nested session" errors
- SSE events use the existing wal_event channel via broadcastAll() — no new SSE endpoint needed
