## 3. Implementation

### Backend changes
- `better-sqlite3` is **synchronous** — no async/await for DB calls
- `db.prepare(sql).get()` → T | undefined; `.all()` → T[]; `.run()` → RunResult
- Always enable WAL + FK on connection (already done in `db/index.ts` — don't duplicate)
- Emit `wal_events` for every state change — this drives the SSE pipeline and audit log
- **New tables**: numbered SQL migration files in `backend/src/db/migrations/` (next available: 039+). **Column additions**: SQLite lacks `ADD COLUMN IF NOT EXISTS` — use `pragma table_info` check in `backend/src/db/index.ts` instead of a migration file.
- `chatComplete()` returns `ChatResult { text: string; usage: TokenUsage }` — always use `.text`

### Frontend changes
- `apiFetch<T>(path, init?)` in `src/lib/apiFetch.ts` — use this for all API calls
- `useWorkspace()` provides `workspaceId`, `workspaces`, `selectedWorkspace`
- Panel components live in `src/panels/`, shared components in `src/components/`
- xterm.js: `@xterm/xterm` + `@xterm/addon-fit` (NOT the old `xterm` package)

### Critical path gotchas
- **Spec path**: `ralph/specs/approved/${spec.id}.json` (NOT `specs/approved/${spec.specName}.json`)
- **spec.id** = filename slug; **spec.specName** = human title (display only)
- **chatComplete** returns `ChatResult` — use `.text` accessor everywhere
- **Pipeline trigger** strips 4 Claude env vars before spawning `execution-engine.ts`
- **execution-engine.ts** (`backend/src/lib/execution-engine.ts`) is the universal TypeScript execution engine — handles claude, opencode, and codex agent paths. Replaces run-loop.sh/run-loop.ts entirely.
- **Backend port 3030** — restart required after any changes (`lsof -ti:3030 | xargs kill -9`)
