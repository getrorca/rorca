## 3. Implementation

### Backend changes
- `better-sqlite3` is **synchronous** — no async/await for DB calls
- `db.prepare(sql).get()` → T | undefined; `.all()` → T[]; `.run()` → RunResult
- Always enable WAL + FK on connection (already done in `db/index.ts` — don't duplicate)
- Emit `wal_events` for every state change — this drives the SSE pipeline and audit log
- **New tables**: numbered SQL migration files in `backend/src/db/migrations/` (next available: 039+). **Column additions**: SQLite lacks `ADD COLUMN IF NOT EXISTS` — use `pragma table_info` check in `backend/src/db/index.ts` instead of a migration file.
- `chatComplete()` returns `ChatResult { text: string; usage: TokenUsage }` — always use `.text`

### Frontend changes
- `apiFetch<T>(path, init?)` in `src/lib/apiFetch.ts` — use this for all API calls
- `useWorkspace()` provides `workspaceId`, `workspaces`, `selectedWorkspace`
- Panel components live in `src/panels/`, shared components in `src/components/`
- xterm.js: `@xterm/xterm` + `@xterm/addon-fit` (NOT the old `xterm` package)

### Critical path gotchas
- **Spec path**: `ralph/specs/approved/${spec.id}.json` (NOT `specs/approved/${spec.specName}.json`)
- **spec.id** = filename slug; **spec.specName** = human title (display only)
- **chatComplete** returns `ChatResult` — use `.text` accessor everywhere
- **Pipeline trigger** strips 4 Claude env vars before spawning `execution-engine.ts`
- **execution-engine.ts** (`backend/src/lib/execution-engine.ts`) is the universal TypeScript execution engine — handles claude, opencode, and codex agent paths. Replaces run-loop.sh/run-loop.ts entirely.
- **Backend port 3030** — restart required after any changes (`lsof -ti:3030 | xargs kill -9`)

Your task (EQ-008):
Build `backend/src/lib/wave-compiler.ts` that takes a spec's `userStories` array and compiles it into an ordered array of waves using Kahn's algorithm. Each wave is a set of stories whose `dependsOn` dependencies all appear in earlier waves — meaning they can be executed concurrently without ordering violations. This module is execution-engine-agnostic: it is called by both `run-loop.ts` (current) and `execution-engine.ts` (after opencode-integration ships). The `parallelGroups` helper already exists in `backend/src/routes/specs.ts` for the graph API — extract and generalise it into this standalone module. Stories with `passes: true` are excluded from compilation (already done). Cycle detection returns a typed error.

Acceptance Criteria:
- `backend/src/lib/wave-compiler.ts` exports `compileWaves(stories: UserStory[]): Wave[] | CycleError`  - `Wave` type: `{ index: number, stories: UserStory[] }` — index 0 is the first wave  - Kahn's algorithm: initialise in-degree map, enqueue zero-in-degree nodes, drain per wave level  - Stories with `passes: true` are excluded before compilation — waves are built from pending stories only  - Cycle detection: if any stories remain after Kahn's drains (in-degree never reached 0), return `{ cycle: true, involvedIds: string[] }`  - Single-story and zero-dependency specs produce a single wave containing all stories  - Stories with `dependsOn` referencing already-passed story IDs treat those deps as satisfied  - Unit tests cover: linear chain (each story depends on previous), diamond DAG, fully independent (all in wave 0), cycle detection, mixed passed/pending  - The existing `computeParallelGroups` helper in `specs.ts` is replaced with a call to `compileWaves` from this module to eliminate duplication
