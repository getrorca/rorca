## Story OC-004: Execution Engine Multi-Agent Switching — DONE
Files touched: backend/src/lib/execution-engine.ts (new file, ~1050 lines)
What was built:
- Universal execution engine replacing run-loop.ts for all three agent types
- runAgent() dispatcher: switches on agentType to spawnClaude/spawnOpenCode/spawnCodex
- spawnClaude: identical to run-loop.ts claude path (--print --verbose --output-format stream-json, prompt as arg)
- spawnOpenCode: `opencode run --format json --attach <addr> --model <model>`, prompt via stdin
- spawnCodex: `codex --approval-mode auto-edit`, prompt via stdin
- ATTACH_ADDR passed via --attach CLI flag (from opencode-server.ts), NOT env var
- AbortController-style timeout: setTimeout + SIGTERM, escalate to SIGKILL after 10s
- Exit code captured from child process 'exit' event (null → 124 timeout code)
- All three paths produce identical WAL events (story_started, story_passed, story_failed) via same emitWalEvent()
- CLI flags: --agent, --model, --attach (override env vars)
- Full wave-parallel execution preserved from run-loop.ts

Key decisions:
- Kept all run-loop.ts behavior (wave merging, worktree isolation, rate limit backoff, validation gate)
- opencode binary resolved via detectOpenCode() from opencode-detector.ts
- codex binary resolved via CODEX_BIN env or `which codex`
- WAL events include agent_type in payload for observability
- agentModel used only for opencode (--model flag); claude uses subscription model, codex has no model flag
