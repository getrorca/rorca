Task (US-013): Embedded TUI: Spec Detail and Run Trigger Modal
Implement a Spec Detail modal overlay in ~/.pi/agent/extensions/rorca/tui/spec-detail.ts that shows the full story list with pass/fail/pending status indicators, acceptance criteria for the focused story, and an action bar for triggering a Pi-native run, retrying failed stories, or viewing run history.

## Context
- **API endpoints**: Fetch spec via `GET /api/specs/{specId}`, runs via `GET /api/pipeline/runs?specId=...`, run detail via `GET /api/pipeline/runs/{runId}`. Pipeline trigger is `POST /api/pipeline/trigger` (not `/runs/external` — that route doesn't exist; check `backend/src/routes/pipeline.ts` for the actual trigger endpoint and required payload shape including `specPath`, `workspaceId`).
- **Spec ID is the filename slug**: `spec.id` is the slug (e.g., `rorca-feature-enhancements`), not the human title. Construct spec path as `forge/specs/approved/${specId}.json`. Never use `spec.specName` for path construction.
- **Story result matching**: Story results use `story_results` table with `story_id` column. Match against `story.id` from `spec.userStories` (the array field is `userStories`, NOT `stories`).
- **Preflight from US-008**: Reuse the preflight function for pre-run validation. Model resolution chain: `story.model → spec.model → RORCA_MODEL env` (no other fallbacks — escalation/cascade system was removed 2026-04-06).
- **Conflict detection on trigger**: The pipeline trigger endpoint checks for active runs and returns `{ conflict: true, activeRunId }` when one exists. Handle both 409 status and the JSON conflict field.
- **MCP async pattern for retry**: If calling retry via MCP, use the async job endpoint pattern (POST async variant → poll `/api/spec-jobs/:jobId`). For direct HTTP, `POST /api/pipeline/runs/{runId}/retry` with `{ storyIds: [...] }` is the correct shape — verify in `backend/src/routes/pipeline.ts`.
- **ANSI rendering**: This is a Pi TUI extension file at `~/.pi/agent/extensions/rorca/tui/spec-detail.ts`. Use raw ANSI escape codes for reverse video (`\x1b[7m`/`\x1b[0m`), colors, and cursor positioning. No React/Ink — this is a terminal-native overlay.
- **Auth token handling**: Bearer token for MCP HTTP is stored at `~/.rorca/mcp-token` (mode 0600). The `token?` parameter should be passed as `Authorization: Bearer ${token}` header on all API calls to `:3030/api/*` endpoints. In local single-user mode, auth middleware is bypassed for `/api/*` but MCP routes always require the token.

Acceptance Criteria:
- File ~/.pi/agent/extensions/rorca/tui/spec-detail.ts exports: async function openSpecDetail(pi: ExtensionAPI, specId: string, baseUrl: string, token?: string): Promise<void>. Invoked by pressing ENTER on a spec card in spec-board.ts (US-012) or directly by /rorca:run <specId> command.
- Data fetch on open: (1) GET /api/specs/{specId} — get spec with userStories. (2) GET /api/pipeline/runs?specId={specId}&limit=1&status=all — get the most recent run if any. (3) If a recent run exists: GET /api/pipeline/runs/{runId} — get storyResults to determine per-story status. Merge: for each story in spec.userStories, find matching storyResult by storyId === story.id. Status icon: '✓' passed, '✗' failed, '↺' running (activeRunStatus includes story), '○' pending (no result). '—' skipped.
- Story list rendering: render in a scrollable list (max visible height = process.stdout.rows - 8, with scroll indicators ↑/↓ when list overflows). Each row: '{icon} {story.id}: {story.title.slice(0,55)}'. Focused row is highlighted with ANSI reverse video. Pressing ENTER on a story toggles inline expansion: the acceptance criteria are shown beneath the row as numbered items, indented with 4 spaces, max 10 shown (with '...N more' if truncated).
- Action bar: rendered at the bottom of the view, showing 3 actions: [R] Run | [F] Retry Failed | [H] History. TAB cycles focus between story list and action bar. In action bar, LEFT/RIGHT arrows move between actions. ENTER activates the focused action. Story list is the default focus on open.
- [R] Run action: (1) Call preflight() from US-008. (2) If preflight.ok === false: render errors in a red panel above the action bar: 'PREFLIGHT ERRORS:\n' + errors.join('\n'). Block run. (3) If preflight.warnings.length > 0: show warnings in amber, prompt 'Proceed despite warnings? (y/N):'. Wait for 'y' to continue. (4) Resolve model via resolveStoryModel(story, spec) for the spec-level model. (5) Call POST /api/pipeline/runs/external with { specPath: 'forge/specs/approved/' + specId + '.json', workspaceId, idempotencyKey: `${specId}-${Date.now()}`, agent: 'pi', model }. (6) On 201 response: close spec detail, open run view (US-014) with the new runId. On conflict (409 or {conflict:true}): notify 'A run is already active (runId: X). Open it? (y/N):'; if 'y', open run view with activeRunId.
- [F] Retry Failed action: get list of failed storyIds from storyResults where status === 'failed'. If none, notify 'No failed stories to retry'. If yes, call rorca_pipeline_retry (or POST /api/pipeline/runs/{lastRunId}/retry) MCP tool for each failed storyId. After each retry call, refresh story statuses.
- [H] History action: show a simple inline list of the last 5 runs for this spec: fetch GET /api/pipeline/runs?specId={specId}&limit=5. Render as: '{runId}: {status} | {storyResults.length} stories | {timeAgo(run.started_at)}'. Pressing ENTER on a run row opens run view (US-014).
- 'q' or ESC exits the spec detail view and returns to spec board if that was the opener, or exits completely if invoked directly.
