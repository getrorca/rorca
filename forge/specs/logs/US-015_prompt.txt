Task (US-015): Embedded TUI: Memory Browser and Proposal Review Modal

## Context
- **API endpoint for memory fetch**: Use `POST /api/recall` with `{ workspaceId, currentTask, limit }` — verify whether `fetchAll: true` is actually supported by checking `backend/src/routes/` for the recall route handler; if not, fall back to `limit: 100` as the acceptance criteria allows.
- **Memory categories are fixed**: Architecture, Convention, Bug Fix, Decision, Pattern, Gotcha, Other — these match the `rorca_save_memory` MCP tool categories defined in `backend/src/mcp/server.ts`. Entries without a `category` field go to "Other".
- **MCP tool name resolution**: The save-memory tool is registered as `rorca_save_memory` in the MCP bridge (confirmed in CLAUDE.md MCP tools table). Verify the exact name the pi extension bridge re-exports — it may be prefixed or aliased during bridge registration. Check the bridge tool list before hardcoding.
- **File I/O for `proposed-memories.json`**: This file lives at `~/.rorca/proposed-memories.json` (not in the workspace). Use atomic write (write to temp file + rename) when removing accepted/deleted entries to avoid corruption if the process is interrupted mid-write. Same for `learning-log.jsonl` appends.
- **Extension API pattern**: Follow the same export signature pattern as other TUI modules in `~/.pi/agent/extensions/rorca/tui/` — `async function openMemoryBrowser(pi: ExtensionAPI, workspaceId: string, baseUrl: string, token?: string): Promise<void>`. - **Debounced search**: The 300ms debounce on `/` search must cancel in-flight `POST /api/recall` requests when new input arrives — use an AbortController per request to avoid stale results replacing fresher ones.
- **TUI rendering constraints**: This runs inside pi's terminal — use raw stdin mode for key handling (j/k/ENTER/TAB/ESC/a/e/d/q). Ensure all key bindings are cleaned up on exit to avoid leaking raw mode into the parent pi session. Restore terminal state in a `finally` block.
- **No external dependencies**: The `readline.question()` usage for the edit flow ('e' key) should use Node's built-in `readline` module — do not add new npm dependencies for this TUI component.
