Task (US-018): Pi Extension Bootstrap, Command Registration, and E2E Integration Test
Implement the Pi extension entry point (rorca-pi-extension/index.ts) that bootstraps all subsystems at Pi session start: MCP bridge tool discovery (US-001), stale run reconciliation (US-009), CAG → RAG → Knowledge Graph context warm-up for the active workspace, TUI widget registration (US-011), and command registration for /rorca:board, /rorca:run, /rorca:memory, /rorca:direction, /rorca:workspace. Write an integration test that simulates a 3-story spec run end-to-end using mocked Pi child-process spawning and a real test Postgres DB.

This bootstrap story chooses the richest supported UI surface at startup, registers the always-on widget, primes the context cache for the current workspace, and guarantees a /rorca-tui subprocess fallback so the user still gets a real TUI even if Pi cannot host modal views.

## Context
- **Extension entry point pattern**: Follow the existing `backend/src/mcp/server.ts` structure for tool/command registration. Use a non-throwing init wrapper — if backend is unreachable at `http://localhost:3030`, log warning and degrade gracefully (zero MCP tools, zero TUI views). Never block Pi session startup on network calls.

- **Integration test location & framework**: Place at `backend/src/__tests__/pi-native-run.test.ts` using Jest (backend test runner, not Vitest). Use a real test Postgres DB — follow existing patterns in `backend/src/__tests__/` for DB setup/teardown. Mock child-process spawning (no real `pi` binary needed).

- **External run API**: `POST /api/pipeline/runs/external` is the endpoint for externally-driven runs. Test idempotency via `idempotencyKey` — second POST with same key must return existing `runId`, not create a duplicate `pipeline_runs` row. Assert `story_results` rows via direct DB query after simulating story result POSTs.

- **Context warm-up**: The CAG → RAG → Knowledge Graph stack lives in `backend/src/lib/context-router.ts` (virtual context routing) and `backend/src/lib/graph-context.ts` (AGE graph enrichment). In Lite Mode (no AGE), graph enrichment returns empty — handle this gracefully. The `workspace-echolocation.ts` `echolocate()` call can pre-scan workspace health.

- **Command registration**: Register `/rorca:board`, `/rorca:run`, `/rorca:memory`, `/rorca:direction`, `/rorca:workspace` as Pi commands. Each should open the corresponding TUI view (US-012–US-016). `/rorca-tui` is the subprocess fallback — spawn with inherited stdio when Pi lacks modal view API.

- **Startup ordering is critical**: Layer 1 (status widget) first → then reconciliation (`US-009` stale run recovery) and MCP tool discovery (`US-001`) → Layer 2 UI detection last. Never block on optional Layer 2 modal/full-screen detection. Use `Promise.allSettled` for parallel non-blocking init of reconciliation + MCP discovery.

- **3-second cold start budget**: Bootstrap must complete in <3s. Avoid synchronous DB queries — use `await` with the async `pg` pool (max 20 connections, 30s idle timeout from `backend/src/db/index.ts`). Context warm-up can run in background after widget registration.

- **TypeScript compilation**: Extension package must pass `npx tsc --noEmit` independently. Use strict mode, no implicit any. Import types from shared backend modules if needed but avoid circular dependencies with the main backend build.

Acceptance Criteria:
- Extension bootstrap completes in under 3 seconds on a cold start with a running Rorca backend; if the backend is unreachable the extension logs a warning and registers zero MCP tools without throwing
- Commands /rorca:board, /rorca:run <specId>, /rorca:memory, /rorca:direction, /rorca:workspace are registered and each opens the corresponding TUI view (US-012 through US-016) when invoked
- The extension preloads context for the active workspace using the same CAG → RAG → Knowledge Graph stack as the prompt builder so the first run has warm cached context instead of cold-starting every retrieval
- Integration test (backend/src/__tests__/pi-native-run.test.ts) creates a 3-story spec, calls POST /api/pipeline/runs/external, simulates 3 sequential story result POSTs, and asserts the run finalizes with status:'passed' and all 3 story_results rows exist in the DB
- Integration test asserts that calling POST /api/pipeline/runs/external twice with the same idempotencyKey returns the same runId without creating a duplicate pipeline_runs row
- npx tsc --noEmit passes for the extension package and cd backend && npm test runs the integration test green
- The extension registers a /rorca-tui command that launches the existing Rorca TUI as a subprocess with inherited stdio when Pi cannot host an embedded modal view.
- If Pi exposes a supported modal/full-screen view API, the extension uses it for the board, spec detail, run, memory, direction, and workspace surfaces; otherwise those commands degrade gracefully and the subprocess fallback remains available.
- Startup prioritizes Layer 1 status widget registration, then reconciliation and MCP discovery, and never blocks the session on optional Layer 2 UI support.
