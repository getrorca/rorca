Task (US-011-RECHECK): Embedded TUI: Always-On Status Widget and WAL Event Ticker
Implement an always-on Pi TUI status widget in ~/.pi/agent/extensions/rorca/lib/status-widget.ts using the Pi ExtensionAPI ctx.ui.setStatus() and ctx.ui.setWidget() APIs (if available). The widget shows active workspace name, current spec/run status, stories passed/total, active model, and a rolling ticker of the last 3 WAL events. Falls back to plain-text stderr output when the Pi widget API is unavailable.

## Context
- **File location**: `~/.pi/agent/extensions/rorca/lib/status-widget.ts` — this is a Pi extension file, NOT in the Rorca backend. It lives in the user's home directory under Pi's extension structure.
- **API endpoints used**: `GET /api/wal?limit=3&orderBy=desc` and `GET /api/specs?status=pending&limit=1` — both hit the Rorca backend at `:3030`. Note: WAL events table uses `ts` column (NOT `created_at`) per CLAUDE.md gotchas. The route handler may alias it, but verify the API response shape.
- **MCP Bearer auth required**: All fetch calls to `localhost:3030` must include `Authorization: Bearer <token>` header when token is provided. Token is read from `~/.rorca/mcp-token` (mode 0600). See CLI-045 security model.
- **sse-hub is process-local**: Do NOT use SSE subscription for WAL events here — the widget runs in a separate Pi process. Polling via HTTP (`GET /api/wal`) is the correct approach (matches the memory note about cross-process delivery).
- **Graceful degradation pattern**: Three layers — (1) full widget API via `ctx.ui.setWidget`, (2) status-only via `ctx.ui.setStatus`, (3) stderr fallback. Detect each with typeof/try-catch. Never throw from tick — all network errors must be silently swallowed.
- **RORCA_TUI_DISABLE env var**: Early-return in `start()` — no interval setup, no API calls, no output. This is critical for CI where stderr noise breaks log parsing.
- **Polling interval**: 5s for normal mode, 10s for stderr fallback mode. Use `setInterval` (not recursive setTimeout) per the acceptance criteria. `stop()` must `clearInterval` cleanly.
- **State coupling with spec-orchestrator.ts**: `setActiveRun()` is called externally by the orchestrator. Ensure the interface matches what the orchestrator expects — particularly `runId: number | null` and nullable fields for the "idle" state.

Acceptance Criteria:
- File ~/.pi/agent/extensions/rorca/lib/status-widget.ts exports: class StatusWidget { constructor(pi: ExtensionAPI, baseUrl: string, token?: string); start(): void; stop(): void; setActiveRun(runId: number | null, specId: string | null, totalStories: number, passedStories: number, model: string | null): void; }
- On start(), the widget calls ctx.ui.setStatus('rorca', 'Rorca: Connecting...') immediately. It then begins a polling loop with setInterval(tick, 5000). Each tick: (1) fetch GET /api/wal?limit=3&orderBy=desc (with 3s timeout, silently ignore errors). (2) Extract last 3 events: map each to `${event.event_type} (${timeAgo(event.ts)})`. (3) If no active run: fetch GET /api/specs?status=pending&limit=1 to get pending count (extract total from response). (4) Compose status line: if activeRunId !== null: `Rorca: ${specId} | ${passedStories}/${totalStories} | ${model||'auto'} | ${lastEvent}`. Else: `Rorca: Idle — ${pendingCount} pending | ${lastEvent||'no events'}`. (5) Call ctx.ui.setStatus('rorca', statusLine).
- Widget API (Layer 1 extended): if pi has a setWidget or equivalent API (detected by typeof ctx.ui.setWidget === 'function'), additionally call ctx.ui.setWidget('rorca-status', { type: 'text', content: statusLine }). This is opportunistic — if the API doesn't exist, skip silently.
- RORCA_TUI_DISABLE: if process.env.RORCA_TUI_DISABLE === 'true', the start() method returns immediately without setting up the polling loop and without calling setStatus(). This suppresses all TUI output for CI environments.
- Fallback mode: if ctx.ui.setStatus throws (detected by wrapping in try/catch), switch to fallback mode: every 10 seconds write a plain one-line status to process.stderr using process.stderr.write(`[rorca] ${statusLine}\n`). Fallback mode is activated once and never re-attempts the setStatus API.
- setActiveRun(runId, specId, totalStories, passedStories, model) updates the internal state used by the tick. The next tick reads from this state.
- timeAgo(ts: string): string helper: returns '< 1m' if ts is within 60s, 'Nm ago' for N minutes, 'Nh ago' for N hours. Uses Date.now() - new Date(ts).getTime().
- stop() calls clearInterval on the polling interval and calls ctx.ui.setStatus('rorca', 'Rorca: Disconnected') as a final status update.
