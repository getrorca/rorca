Task (US-012): Embedded TUI: Spec Board Interactive View
Implement an interactive Kanban-style spec board as a Pi TUI command in ~/.pi/agent/extensions/rorca/tui/spec-board.ts. The board shows specs grouped by status (Draft, In Progress, Done), supports keyboard navigation, and dispatches MCP tool calls for approve/reject actions. If Pi does not expose a modal/overlay API, renders as a text-based interactive table using process.stdout with readline.

## Context
- **File location & export**: Must be `~/.pi/agent/extensions/rorca/tui/spec-board.ts` with exact signature `async function openSpecBoard(pi: ExtensionAPI, baseUrl: string, token?: string): Promise<void>`. This is consumed by the `/rorca:board` command registered in US-018 — coordinate the import path.

- **Kanban API contract**: `GET /api/specs/kanban?workspaceId={id}` returns columns with spec cards containing `activeRunStatus`, `queuePosition`, `storyCount`, `model`, and timestamps. Grouping logic: draft = `status === 'pending'`, in_progress = `activeRunStatus === 'running' | 'queued'`, done = `status === 'passed'`. See `backend/src/routes/specs.ts` kanban route and `KanbanSpec` interface in `src/panels/SpecsPanel.tsx` for the exact response shape.

- **MCP bridge for approve**: Use `rorca_approve_spec` MCP tool (defined in `backend/src/mcp/server.ts`) via the Pi MCP bridge with `{ specId: card.id }`. Remember: `spec.id` is the filename slug, never the human title. No MCP tool exists for reject — use direct `DELETE /api/specs/{id}` HTTP call with Bearer token auth header if token is provided.

- **Terminal raw mode gotcha**: When entering raw mode (`process.stdin.setRawMode(true)`), you MUST restore it on exit (`setRawMode(false)`, `pause()`) in ALL exit paths — including error throws and unhandled rejections. A leaked raw-mode stdin will break the parent Pi process. Wrap the entire board lifecycle in try/finally.

- **Pi modal API detection**: Runtime-check `typeof ctx.ui.showModal === 'function'` before using it. The fallback path (readline + ANSI) is the primary implementation since Pi's modal API may not exist yet. ANSI reverse video (`\x1b[7m`) for focus, `\x1b[0m` to reset. Use `\x1b[2J\x1b[H` to clear screen on re-render.

- **Arrow key sequences**: Arrow keys arrive as 3-byte escape sequences (`\x1b[A` through `\x1b[D`). Parse the `data` buffer carefully — a bare `\x1b` (ESC) without `[` following it means quit. Don't confuse ESC-prefix arrow sequences with the standalone ESC key.

- **Auto-refresh cursor preservation**: The 30s interval re-fetch must clamp the cursor position to the new column length (`Math.min(cursorRow, column.length - 1)`). Don't reset column focus index on refresh — only clamp within bounds.

- **Auth header**: Pass `Authorization: Bearer ${token}` on all HTTP calls (both kanban fetch and reject DELETE). The MCP bridge handles its own auth, but direct HTTP calls need the header explicitly. Token comes from `~/.rorca/mcp-token` (mode 0600).

Acceptance Criteria:
- File ~/.pi/agent/extensions/rorca/tui/spec-board.ts exports: async function openSpecBoard(pi: ExtensionAPI, baseUrl: string, token?: string): Promise<void>. This function is invoked by the /rorca:board command registered in US-018.
- Data fetch: GET /api/specs/kanban?workspaceId={activeWorkspaceId}. Parse columns from response. Extract three groups: draft (status === 'pending' or column === 'draft'), in_progress (activeRunStatus === 'running' or activeRunStatus === 'queued'), done (status === 'passed' or column === 'done'). Each spec card shows: title (max 50 chars, truncate with '...'), story count (storyCount or userStories.length), model badge (spec.model || 'auto'), time-ago created. Empty groups show 'No specs in this column.'
- Rendering: if typeof ctx.ui.showModal === 'function' (or equivalent Pi modal API, detected at runtime), use it. Otherwise, render to process.stdout using Node.js readline and ANSI escape codes. The rendered board is a 3-column layout: [DRAFT] | [IN PROGRESS] | [DONE]. Columns are separated by '│'. The currently focused card is highlighted with ANSI reverse video (\x1b[7m). Render function is called on every state change (keypress, refresh).
- Keyboard navigation: intercept keypress events via process.stdin in raw mode (process.stdin.setRawMode(true); process.stdin.resume(); process.stdin.on('data', handleKey)). Key bindings: 'j' or DOWN arrow (\x1b[B) — move cursor down within column. 'k' or UP arrow (\x1b[A) — move cursor up. 'h' or LEFT arrow (\x1b[D) — move to previous column (wrap around). 'l' or RIGHT arrow (\x1b[C) — move to next column. 'a' — approve focused card. 'x' — reject focused card. ENTER — open Spec Detail (US-013). 'r' — force refresh. 'q' or ESC (\x1b) — exit board. Tab — cycle columns.
- 'a' (approve): if focused card is in the draft column, call MCP tool 'rorca_approve_spec' (or 'forge_spec_approve' if renamed) via the bridge with { specId: card.id }. Show a toast: ctx.ui.notify(`Approving ${card.title}...`, 'info'). On success: ctx.ui.notify(`✓ ${card.title} approved`, 'success'). On error: ctx.ui.notify(`✗ Approve failed: ${error}`, 'warning'). Then refresh the board.
- 'x' (reject): call DELETE /api/specs/{card.id} via fetch (not via MCP — no MCP reject tool exists). Confirm first: print 'Reject ${card.title}? (y/N): ' and wait for 'y' keypress before calling. On success, refresh board.
- Auto-refresh: set up a 30-second setInterval that re-fetches the kanban data and re-renders without resetting cursor position (cursor stays on same column index, clamped to new array length). Pressing 'r' clears and restarts the 30s interval.
- Exit: on 'q' or ESC: process.stdin.setRawMode(false), process.stdin.pause(), clear the board from stdout with ANSI clear sequences, and return from the async function. The extension command handler resumes normally.
