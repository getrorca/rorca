## Gap found and fixed

Fresh migration 050 failed because the migration runner creates application schema `rorca` before AGE calls `create_graph('rorca')`; AGE requires that same schema name for graph storage and refused the collision. The failed extension transaction then left AGE unavailable to later DDL.

`050_knowledge_graph.sql` now bridges this transactionally by renaming the pre-AGE application schema, creating/registering the AGE graph, relocating pgcrypto/pgvector to `public`, moving application relations/functions into the graph-owned `rorca` schema, refusing unsupported leftovers, and removing the bridge schema. Existing registered graphs skip the bridge. A focused regression test and the real fresh-install run cover the fix.
