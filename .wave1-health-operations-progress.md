## Profiling evidence

Baseline `GET /api/health` is not a bounded liveness probe. Its cold path:

1. runs six component/job checks concurrently (`dbHealthCheck`, worker, GitHub, migrations, active jobs, schedules), comprising multiple database round trips and filesystem reads;
2. runs another active-run count query;
3. synchronously probes the selected CLI, Pi, and then every engine; Pi is probed twice;
4. each synchronous CLI probe permits a five-second timeout and blocks the Node event loop.

A read-only local executable sample on 2026-07-14 measured `pi --version` at 337.3/334.6/397.6 ms. Since the route invokes Pi twice on a cold cache, executable probing alone contributes about 0.67–0.80 s here; the coded worst case is multiple five-second blocking probes. Missing OpenCode/Codex and `which claude` samples were about 10 ms each. This explains why basic health is materially slower than detailed health and why a >5 s timeout is possible. Database contention adds to that cost.

Planned contract: make `/api/health/live` process-only; make `/api/health` and `/api/health/ready` use one bounded database/read-active-runs probe and fail closed when readiness cannot be confirmed; move engine/component/job/filesystem diagnostics to `/api/health/detailed`. Test the deadline with fake timers/deferred promises rather than wall-clock thresholds.

## Design

### Bounded health

- `GET /api/health/live` is process-only and performs no database, filesystem, or executable work.
- `GET /api/health` and `GET /api/health/ready` share one readiness query for connectivity, extension capability, and the active-run count. A 750 ms deadline returns HTTP 503 with `active_runs: null` and `readiness.confirmed: false`; it never guesses zero.
- `GET /api/health/detailed` owns multi-query component/job checks, filesystem inventory, backup checks, and synchronous CLI detection.
- EngineSelector, provider settings, and CLI Pi auth status now request detailed health; basic capability/onboarding and active-run consumers remain on the bounded route.
- Deadline behavior is tested with injected deterministic timers and a deferred promise, not elapsed wall-clock thresholds.
